# Product

## Register

product

## Users

**Members** — fitness enthusiasts attending classes at Ilannatek studio. They book on mobile between commutes and at home on laptop. Primary task on any screen: see what's available this week and book it in as few taps as possible.

**Instructors** — run classes, manage substitution requests. Occasional power users; need clarity on who's coming and what's changed.

**Studio admin** — Sacha's team. Manages the full operation: members, credits, subscriptions, billing, communications. Uses the admin panel on desktop throughout the workday as a tool, not a visit.

## Product Purpose

Ilannatek is a boutique fitness studio management platform. It replaces WhatsApp chaos and spreadsheets with a clean booking system. Members see the schedule, book classes, manage credits and subscriptions. Admins run the studio: track attendance, handle payments, send comms, monitor churn.

Success: a member can book their next class in under 30 seconds. An admin can see the health of the studio in one glance.

## Brand Personality

Precise. Warm. No-nonsense.

The studio brand is boutique and personal — not a chain, not a tech startup. The tool should feel like it belongs to a studio with real regulars who've been coming for years. Confident without trying hard.

## Anti-references

- **Mindbody** — cluttered, overwhelming, every button fights for attention
- **Generic SaaS dashboards** — teal + purple, floating cards, hero metrics, glassmorphism
- **AI-default cream/sand** — warm beige backgrounds (#F7F3EC and similar) that signal "this was generated"
- **Feature-dump welcome screens** — 9 cards with emoji explaining every possible feature instead of showing the user their actual data

## Design Principles

1. **Show data, not features.** The welcome screen shows the member's next class and credit balance — not a guide to what the app can do.
2. **One primary action per screen.** Every page has a clear, obvious next step. Competing CTAs are a sign that the IA needs work.
3. **The tool disappears into the task.** Consistent components, no invented affordances, no decorative motion. Members should never notice the UI.
4. **Earned familiarity.** Component vocabulary stays consistent across every screen — same button shape, same input style, same status indicators. A "save" button looks identical in every context.
5. **Mobile-first, not mobile-only.** Members book on phone; admins run the studio on desktop. Both experiences must be complete, not degraded.

## Accessibility & Inclusion

- WCAG AA minimum. Body text ≥ 4.5:1 against background.
- Reduced motion support on all transitions.
- Touch targets ≥ 44px on mobile nav and booking CTAs.
- French-language UI throughout; error messages must be actionable, not technical.
